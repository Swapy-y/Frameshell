# Frameshell manual

The full guide: every app, panel, key and setting. For a quick start see the [README](../README.md).

Frameshell is a dark `#1a1a1a` frame with a 2px `#313131` border around a rounded wallpaper window, a notch/island at the top, a running-apps bar at the bottom, and panels that grow out of the frame with concave "ears".
Built for **CachyOS · NVIDIA · one monitor · US keyboard**.

```
┌ hover top-left: volume + brightness ───── notch (hover → island) ────── hover top-right: colour picker ┐
│                                                                            (notifications arrive here) │
│ clipboard: hover the middle of the left edge            quick note: hover the middle of the right edge │
│                                                                                                        │
└ power ───────────────────────────────── running apps ───────────────────────────────── date → calendar ┘
```

## 1 · Install

```bash
git clone https://github.com/Swapy-y/frameshell.git && cd Frameshell
./install.sh            # asks before the big steps; --yes answers yes to everything
```

Then **reboot and pick the “Hyprland” session** on the new login screen (the login screen changes with the next boot; without the login-screen step, logging out is enough unless the installer asks for a reboot — NVIDIA modesetting and the `i2c` group need one).

The installer: updates the system (`pacman -Syu`), installs the apps below (official repos first, AUR via `paru`/`yay` for the rest — with no working AUR helper it installs `paru` from your repos (CachyOS has it) or builds it from the AUR, and replaces a `paru-bin`/`yay-bin` that broke after a pacman update), checks the NVIDIA driver / modesetting / suspend services, sets up DDC brightness, starts Bluetooth, backs up anything it would overwrite to `~/.config/frame-backup-<date>/`, copies the configs, fonts, the Frame GTK theme and the wallpapers, makes Simp1e the computer's default cursor, Nautilus the default file manager, Celluloid the default video player, VS Code the default for code files and GNOME Text Editor for text files, gives four apps plain names (Terminal, Files, Text Editor, System Monitor), and — after asking — downloads the **YAMIS** icon pack (see section 6), makes **Pixie** your login screen and **arch-darwin** your boot screen (see section 7).
Useful flags: `--dry-run` (shows everything, changes nothing), `--no-packages` (config files only), `--no-nvidia`, `--no-icons`, `--no-login` (keep your login screen), `--no-boot` (keep your boot screen).
Off unless you ask for them, also with `--yes`: `--grub` (hide the GRUB menu and boot quietly, section 7), `--english-locale` (the whole system in English: `/etc/locale.conf` becomes `LANG=en_US.UTF-8`, the old file is kept as `locale.conf.frameshell-backup`) and `--firefox-keys` (the author's Firefox shortcuts, see the Firefox row below).

**Notifications start switched off** (the round bell button is a grey circle, “Notifications off”). Hover the notch and click the bell to turn them on — it remembers the choice. To start with them on, set `startWithNotificationsOn: true` in `Config.qml`.

## 2 · The apps (and why)

Four apps go by plain names in the launcher, the app switcher, the bottom bar and other apps' menus: kitty is **Terminal**, Nautilus **Files**, GNOME Text Editor **Text Editor** and Mission Center **System Monitor** (section 5, “App names”).

| Job | App | Notes |
| --- | --- | --- |
| Compositor | **Hyprland** (Lua config, ≥ 0.55) | `~/.config/hypr/hyprland.lua` |
| Desktop UI | **Quickshell** (`qs -c frame`) | frame, notch/island, bottom bar, panels, wallpaper, **app launcher**, app switcher **and the notification daemon** — don't run mako/dunst next to it |
| Launcher | the shell's own launcher | `SUPER+R` |
| Terminal | **kitty** (+ **fish** and **fastfetch** configs) | `SUPER+Q`. Your old ones are backed up |
| Files | **Nautilus** (+ gvfs, File Roller for archives) | `SUPER+E` (a new window at your home folder: `nautilus --new-window`). The installer makes it the **default file manager**: folders opened from any app (“Open folder”, `xdg-open ~/Downloads`) and “Show in folder” in browsers go to Nautilus, even with another file manager installed. With YAMIS it keeps YAMIS's file-manager folder icon (`system-file-manager.svg`), also if a later YAMIS draws Nautilus differently. | Browser | **Firefox** | `SUPER+B`. With `--firefox-keys` the installer copies `config/firefox/customKeys.json` (the author's keyboard shortcuts — `Ctrl+X` closes the tab, `Ctrl+W` opens one, `Ctrl+Q` / `Ctrl+E` back / forward, `Ctrl+S` search, `Ctrl+D` downloads, `Ctrl+1`…`5` tabs …) into every Firefox profile, next to its `chrome` folder; a profile's own `customKeys.json` goes to the backup folder. A profile Firefox makes later gets it at the next start of the shell. Change them in Firefox: `about:keyboard` |
| Text editor | **GNOME Text Editor** (`gnome-text-editor`) | `SUPER+N` (a new window: `gnome-text-editor --new-window`). The default app for **.txt** and other plain text (logs, READMEs, files without a known type) |
| Video player | **Celluloid** (mpv underneath) | the installer makes it the **default video player**: every video type it can play (mp4, mkv, webm, avi, mov …) opens in it from Nautilus, Firefox's downloads and anything else that uses `xdg-open`. Music keeps its current app |
| Code | **VS Code** (AUR `visual-studio-code-bin`; `code` from the repos works too) | from the launcher. The installer makes it the default app for **code files** (Python, C/C++, Rust, Go, JS/TS, HTML/CSS, JSON/YAML/TOML, shell scripts, Markdown, Makefiles, Dockerfiles …; the list is `CODE_TYPES` in `install.sh`). Config files too (.conf, .ini, .cfg, .env, .gitignore, .bashrc, .zshrc …). `config/mime/frameshell-code.xml` teaches the system the code and config files it doesn't know (.tsx, .vue, .zig, .swift, .nix, Dockerfile, .conf, .env …) |
| Chat | **Vesktop** (Discord, AUR `vesktop-bin`) | from the launcher |
| System monitor | **Mission Center** (`mission-center`) | from the launcher: CPU, memory, disks, network and GPU use, and the running apps and processes |
| Login screen | **SDDM** with the **Pixie** theme | replaces your current login manager from the next boot (section 7). It fades in from black, and after you log in the whole desktop (wallpaper, frame, bar) fades in together. A short black moment between the two stays: that is SDDM handing the screen to Hyprland (and back when you log out), when neither draws |
| Lock / idle | the shell's own lock screen (**Pixie**'s look) + **hypridle** | `SUPER+Escape`; it fades in over the desktop and, after the right password, fades out again. Nothing happens on its own when you are idle — no automatic lock, screen off or suspend (the listeners in `hypridle.conf` turn them back on). **hyprlock** takes over if the shell's lock screen ever fails |
| Boot screen | **Plymouth** theme **arch-darwin** | replaces the CachyOS boot animation |
| Boot loader | **GRUB**, only with `--grub` | the boot menu hidden (`Esc` while starting shows it) and a quiet boot (section 7) |
| Clipboard | **wl-clip-persist**, **cliphist + wl-clipboard** | what you copy stays copied after you close the app you copied it from (`wl-clip-persist` keeps a copy of the clipboard; only the normal Ctrl+C clipboard, not the select-to-paste one). The history is the Clipboard panel on the left edge (hover the middle of it) |
| Colour picker | **hyprpicker** | hover the top-right corner, click the small block that pops out |
| Screenshots | the shell's own screenshot screen | `Print`: the screen freezes and dims (it fades in). Drag over an area — letting go keeps it, nothing is taken yet — then move it (drag inside it) or resize it (drag its edges or corners; there are no handles, the pointer shows where you can grab — or drag with the **right** button anywhere: the corner nearest the pointer follows it, like `SUPER` + right drag resizes a window), or drag outside it for a new one; while you size it, its size in pixels shows in its middle. **Middle-click** anywhere for the drawing tools — pencil, line, arrow, rectangle, text — the colour and undo (`Ctrl+Z`); the mouse wheel sets the line width (and the text size). `Enter` (or `Ctrl+C` / `Ctrl+S`) saves the selection — without one, the whole screen — to `~/Pictures/Screenshots` **and** copies it; `Esc` (or `SUPER+C`, from anywhere — also with the menu open or while typing a text) cancels; it fades out either way. The arrow keys move the selection by a pixel, with `Shift` they resize it. While it is open no shortcut works, not even `SUPER` + drag (`SUPER+Ctrl+Alt+Esc` is the emergency way out). `Shift+Print`: the screen the pointer is on, at once. The pointer is in the picture — switch that off with **Capture cursor** on the Settings app's **Screenshot** page. A “Screenshot saved” notification shows it — click it and Nautilus opens the folder with the file selected (`nautilus --select`) |
| Emoji | the shell's own emoji picker | `SUPER+.`: the launcher's look with a grid of emoji under a search field. Type to search by name and keywords (`heart`, `thumbsup`, `flag poland` — several words must all match); the arrow keys move, `Page Up` / `Page Down` by a page, `Tab` / `Shift+Tab` jump to the next / previous group, the row at the bottom jumps to a group with a click (and ends a search). `Enter` or a click picks one: it is copied, and when you were typing in a text field it goes straight into it — the way an input method (fcitx5, IBus) puts text in, so it works in GTK and Qt apps, Firefox and kitty without anything extra (`scripts/emoji.sh`, `scripts/emoji-insert.py`). Apps that don't tell Hyprland when a text field has the focus (Electron apps like VS Code or Discord, X11 apps) get it typed with **wtype** instead; without wtype, paste it there with `Ctrl+V`. While another input method is running (fcitx5, IBus) wtype types it too. The ones you picked last come first (**Recently used**, two rows). `Esc`, `SUPER+.` again or a click beside it closes it, and so does any other shortcut, like the launcher's. The emoji (Unicode 15.1, without skin tones) are in `components/emoji.js`, made from emojibase by `tools/make-emoji.py` |
| On-screen keyboard | the shell's own | `SUPER+\`: an English (US) keyboard floating over the windows, in the middle near the bottom of the screen. A click on a key types it into the focused window; held, it repeats (at the Settings app's **Repeat delay** / **Repeat rate**). It never takes the focus and is not tiled: everything beside it stays clickable — click the window you want to type into, then the keys. `Shift`, `Ctrl` and `Alt` hold for the next key (click again to let go, white while held), `Caps` stays until you click it again; `Esc`, `Tab`, `Enter`, the arrows. The key left of the arrows (or `SUPER+\` again) hides it. With **Focus on cursor** on, the window under the pointer gets the focus as you move to the keyboard, so move straight onto it from the window you type into |
| Audio | **PipeWire + WirePlumber**, `pavucontrol`, `playerctl` | volume slider is in the top-left panel |
| Brightness | **ddcutil** (monitor over DDC/CI), `brightnessctl` for laptops | slider in the top-left panel |
| Wi-Fi / Bluetooth | **NetworkManager** + **BlueZ** (`bluez`, `bluez-utils`) | the Wi-Fi and Bluetooth cards (the island's buttons). The installer switches Bluetooth on (`bluetooth.service`). NetworkManager is CachyOS's default; if another service runs your network (iwd, systemd-networkd), the Wi-Fi list says “NetworkManager isn't running”. Networks with a company / school sign-in (802.1X, e.g. eduroam) are set up once with `nmtui`, and devices that ask for a PIN code with `bluetoothctl`; after that the list connects them |
| Auth dialogs | the shell's own (Quickshell polkit agent) | the password card when an app needs admin rights (pkexec, saving a system file …), styled like the launcher. **hyprpolkitagent** stays installed and takes over by itself if the shell can't do it |
| Portals | **xdg-desktop-portal-hyprland + -gtk** | screen sharing + file pickers |
| Theme | **Frame** GTK theme (the shell's colours on top of **adw-gtk3-dark**), **Frame** Kvantum theme for Qt 5 and Qt 6 (the same colours on **KvLibadwaita**'s shapes), set through **qt5ct** / **qt6ct** | GTK 3, GTK 4 and libadwaita apps in the shell's greys: `#1a1a1a` windows, `#313131` outlines, grey selections, white main buttons with dark text, white switches and checkboxes. Qt apps (Qt 5 and Qt 6) match them: `#1a1a1a` windows and menus, `#313131` buttons and fields, grey selections, white checkboxes, radio buttons and sliders with dark marks |
| Icons | **YAMIS** (Yet Another Monochrome Icon Set), Papirus-Dark as the fallback | app icons everywhere; `qt6-svg` (and `qt5-svg` for Qt 5 apps) is needed to draw them |
| Cursor | **Simp1e Adw Dark** (AUR `xcursor-simp1e-adw-dark`) | everywhere: Hyprland, GTK, Qt and XWayland apps, the login screen, the computer's default cursor (see section 7) |
| Fonts | **Clarity City** (bundled), JetBrains Mono Nerd, Noto | Clarity City is used by the shell, hyprlock and GTK |

## 3 · Using the shell

| Do this | Get this |
| --- | --- |
| look at the notch | workspace pills (the current one is the bigger white pill) · 12-hour clock · signal icon + battery (no battery → always full) |
| hover the notch | it grows: clock + date, the round **Bluetooth** and **Wi-Fi** buttons (white = on, grey = off; a click opens the list), what is playing (the cover or the video's picture, the title and the artist or channel) with the progress bar and the media buttons under it, and the notifications pill (click its round bell button to switch notifications on / off) |
| click the Wi-Fi icon in the island | a card opens in the middle of the screen, like “Shut down?” (the desktop dims): the Wi-Fi icon with the on/off switch, what you are connected to, the cable (when one is plugged in), then the networks — connected first, saved ones next, then by signal. Click a network to join it: a password field opens for a locked one (🔒), `Enter` or Join connects, `Esc` closes it; a wrong password asks again. Click the connected one to disconnect; hover a saved one for **Forget**. **Done**, `Esc` or a click outside the card closes it (in the password field `Esc` first closes the field) |
| click the Bluetooth icon in the island | the same for Bluetooth: the switch, then your devices — connected ones first (with the battery level when the device reports it), paired ones, then new devices found while the card is open (put them in pairing mode). Click to connect / disconnect; a new device is paired, trusted and connected in one click. Hover a paired one for **Forget**. For a keyboard shortcut: `qs -c frame ipc call ui wifi` / `… ui bluetooth` |
| `SUPER+Ctrl+←` · `SUPER+Ctrl+→` | **wallpaper switcher**: the notch grows into a strip of your wallpapers in a loop — the one it is on in the middle, a little bigger, with a white outline, and one on each side (outlined like an unfocused window) — and slides to the previous · next one (the same 0.3 s slide as switching workspaces). Flick through as many as you like: the desktop doesn't change yet. **`Enter`** (also with SUPER still held) makes the one in the middle your wallpaper — it fades in while the switcher closes; **`Esc`** or a click outside the switcher closes it and your wallpaper stays. A click on a picture beside the middle slides to it, a click on the one in the middle is `Enter`; while it is open the arrow keys alone (`←` / `→`) move it too. Above the pictures: where you are (`3 / 7`) on the left, the keys that browse (`‹` `›` Browse) on the right. The login and lock screen take the same picture |

Noir is black `#000000` with `#060606` cards, fields, buttons, selections and hover highlights; Mocha is [Catppuccin Mocha](https://catppuccin.com/palette/) with Mauve buttons and checkboxes. Running GTK 3 apps change at once, GTK 4 / libadwaita and Qt apps the next time they start. `Esc` or a click outside the switcher closes it and your theme stays; a click on a card beside the middle slides to it, a click on the one in the middle is `Enter`; the arrow keys alone move it too while it is open (`←` / `→`, and `↑` / `↓` like with SUPER+Ctrl); above the cards, like the wallpaper switcher: where you are (`2 / 3`) and the keys that browse; the Settings app's **Theme** page switches with one click. The themes and their colours are in `Config.qml` (`themes`: every colour the shell draws with, each explained at Default; edit them or add your own — a colour a theme leaves out is Default's); your pick is kept in `~/.local/state/frameshell/theme` (`scripts/theme.sh` switches GTK, Qt, kitty and Firefox; a GTK or Kvantum theme, kitty config or Firefox `userChrome.css` / `userContent.css` you chose yourself, not a Frame one, is left alone — the installer moves a profile's own two files to the backup folder once). the window borders and kitty switch too (each theme's two border colours: `activeHint` — the focused window — and `inactiveHint` — the others — in its entry in `Config.qml`, which `hyprland.lua` also reads when Hyprland starts; kitty has a config per theme, `frame.conf`, `frame-noir.conf` and `frame-mocha.conf` in `~/.config/kitty`, and `kitty.conf` is a link to the one in use — open kitty windows change at once) — and **Firefox**: each theme has its own `userChrome.css` and `userContent.css` (`~/.config/frameshell/firefox/<theme>/`), every Firefox profile's `chrome/userChrome.css` and `chrome/userContent.css` are links to the ones in use, and Firefox shows the change the next time it starts (a profile Firefox makes later gets them at the next start of the shell; the setting Firefox needs for them, `toolkit.legacyUserProfileCustomizations.stylesheets`, is turned on in the profile's `user.js`) |
| click a workspace pill | go to that workspace. There are always 4 pills (white = the one you are on). Open a window on the last pill and the next one appears; pills above the fourth disappear again when their workspace is empty. The fifth workspace is the last one (`workspaceCount` / `workspaceMax` in `Config.qml`) |
| `SUPER+R`, type “settings” | **Settings** — the shell's own settings app (a normal tiled window, in the dock and the app switcher like any app; `qs -c frame ipc call ui settings` opens it too). A search field and fourteen pages (they scroll when the window is low). **Blur**: **Apply blur to windows** (Hyprland blurs what is behind see-through windows, like kitty — it makes no window see-through itself) and **Apply blur to shell** (the frame, the island, the panels and the pop-ups become see-through with a blur behind them; their text and icons stay solid), with sliders for the **Shell opacity** (50–100 %, 80 % by default) and Hyprland's blur **Size**, **Passes**, **Brightness** and **Contrast** (7, 2, 1.00 and 0.90 by default) — kept in `~/.local/state/frameshell/blur.json`, which `hyprland.lua` reads when Hyprland starts (the rules `frame-window-blur` and `frame-shell-blur`); a change applies at once. **Presets**: your look under a name — the wallpaper, the theme, the **Appearance** and **Blur** pages and the island's and the dock's switches (**Auto hide**, **Notch mode**). To save: type a name, **Save** (or `Enter`) — the settings you have now become a preset (a name you saved before saves over it; Default and Swapy can't be saved over). One you saved shows a small red bin in its corner while the pointer is on it: a click deletes it. Kept in `~/.local/state/frameshell/presets.json` (`services/Presets.qml`); the pinned apps, the devices and the notifications are not part of a preset (a preset's wallpaper you have since removed is left as it is). **Wi-Fi**: one card like the Devices sections — the on / off switch on the right of its heading (which says what you are connected to, or why Wi-Fi is not there); while Wi-Fi is on the card is open with the networks nearby, like the island's Wi-Fi card: the cable when one is plugged in, the connected network first, saved ones next, then by signal. A click joins a network (a locked one, 🔒, opens a password field under it: **Join** or `Enter` connects, `Esc` closes it; a wrong password asks again) or disconnects the one you are on; **Forget** on a saved one. **Bluetooth**: the same — the switch (the heading says what is connected); while Bluetooth is on the card is open with your devices and new ones nearby (searched for while the page is open: put one in pairing mode): a click connects, disconnects or pairs; **Forget** on a paired one. **Devices** (each section opens when you click its heading — the arrow on the right): **Output** and **Input** — the volume and mute of the speakers / headphones and the microphone in use, and the devices to pick from (a click makes one the one in use: PipeWire's default, apps follow it); **Keyboard** — **Repeat delay**, **Repeat rate** and **Num Lock** (the layout is English (US): `kb_layout` in the “INPUT” section of `hyprland.lua`); **Mouse** — **Speed**, **Acceleration** (on by default), **Scroll speed**, **Natural scrolling**, **Focus on cursor** (off: a click focuses a window, as before; on: the window under the pointer gets the focus) and **Cursor follows focus** (on: focusing a window with the keys moves the pointer to it; off: the pointer stays) — kept in `~/.local/state/frameshell/system.json`, which `hyprland.lua` reads when Hyprland starts; a change applies at once; **Touchpad** (only when there is one) — **Tap to click**, **Natural scrolling**, **Off while typing**, **Scroll speed**. The keyboard, mouse and touchpad settings are kept in `~/.local/state/frameshell/input.json`, which `hyprland.lua` reads when Hyprland starts (its INPUT section); a change applies at once. **Screenshot**: **Capture cursor** (on by default) — the pointer is in the picture, where it was when you pressed `Print` (kept in the shell's `state.json`). **Keybinds**: every keyboard shortcut, as Hyprland has them now (`hyprctl binds -j` — also ones you add to `hyprland.lua`, with the `description` they have there), one row per action with its keys (the same action on more keys in one row; the workspaces' number keys as `1–5`), in four cards: windows, workspaces and screens, apps and the shell, sound and music. **System**: your **picture** and **name**, as the lock and login screen show them — **Change picture** opens a file dialog, the picture is cut square in the middle and saved to `~/.face` and to the login screen's copy; with a picture set, a small red bin shows in its corner while the pointer is on it (like on a wallpaper you added): a click takes it away (`~/.face` goes to the trash) and the first letter of your name is back; **Change name** turns the name into a field, **Save** (or `Enter`) asks for your password (`pkexec usermod -c`: it is your full name in `/etc/passwd`), **Cancel** (or `Esc`) leaves it (`services/Profile.qml`, `scripts/profile.sh`); under it **About** — the operating system (with its logo, when the icon is there), the shell (Frameshell), the versions of Hyprland and Quickshell, the kernel, the computer's name, the processor, the memory, the graphics and the disk the system is on (read when the page opens: `scripts/about.sh`; a row with nothing found is left out). **Theme**: the colour themes as cards, like the theme switcher's (the one in use has a ring) — click one to switch to it, with GTK and Qt apps, kitty, Firefox and the window borders. **Appearance**: four sliders, like the volume and brightness ones — **Window border** and **Frame border**, 0–4 px (2 by default; section 5, *Border and corners*), **Corner rounding**, 20–30 px (30 by default: the frame's four corners round the windows and the windows' corners), and **Window gap**, the space round every window, 5–20 px (15 by default; the tiles move to it at once). Under them **Use Frameshell logo as power button** (on by default: the bottom bar's power button shows the Frameshell logo — four rounded corners of a frame; off: the power sign), and **App icons**: the icon pack of the apps in the shell — the dock, the launcher, the app switcher, the notifications — as cards with a few of your apps in each (the dock's pinned ones first): **YAMIS** (the default), **Adwaita** (GNOME's: the apps' own icons) or **Papirus** (flat and colourful — its Dark variant, installed with frameshell as YAMIS's fallback); a click switches at once (kept in the shell's `state.json`; GTK and Qt apps keep YAMIS — section 6). **Wallpaper**: your wallpapers as tiles (the one in use has a ring) — click one to make it the wallpaper, the last tile (**+ Add**) opens a file dialog and copies the pictures you pick into the wallpaper folder; or drag pictures from the file manager onto it. Both come out *over* your windows (the windows keep their size and place: with auto hide the space is not reserved for them) and go away when the pointer leaves them; the dock also stays while the power menu or the calendar is open (`SUPER+,` brings it out with the calendar). The **Dock** page also has **Pinned apps**: **Add** lists the apps you have installed, with a search field — click one (or press Enter for the first) to pin it; the arrows move a pinned app left / right in the dock, **Unpin** takes it out. Pinned apps sit first in the dock, with a short rounded line between them and your other open apps. A click opens a pinned app, or goes to its window when it is open; a middle-click closes that window. Its icon stands for its first window (grey while you are on it) — more windows of it (a second terminal) show after the line like any app's — and a pinned app that is not open is a bit darker |
| `SUPER+R` | **app launcher**: type to search (`chrm` finds Chromium, several words must all match), `↑ ↓` / `Tab` move, `Enter` launches, `Esc` or a click outside it closes it (also with SUPER held: SUPER + drag doesn't move windows while it is open) — and so does any other shortcut (`SUPER+arrows`, `SUPER+Q`, `SUPER+Space` …), which then does what it does. Apps you launch often move to the top |
| click the power icon (bottom-left) | Shut down (asks “Shut down?” first — `Enter` / Shut down confirms, `Esc` / Cancel / a click outside goes back; no countdown) · Restart · Lock (the Pixie lock screen) · Log out (asks “Log out?” first; then the screen fades to black, every app is closed and the login screen fades in) |
| click the date (bottom-right, or `SUPER+,`) | calendar: the month and year on the left, the round ‹ › buttons (or the mouse wheel) change month, click the month name to jump back; today is the white circle |

| hover the middle of the right edge, click into the panel | quick note — grows with the text (longer notes scroll), saved to `~/.local/state/quickshell/by-shell/…/quick-note.txt`; `Esc` stops editing. The round **Save** button next to the title (floppy disk) saves a copy of the note to a text file you pick. The file dialog is zenity's (the installer adds it; `scripts/note.sh`) |
| hover the middle of the left edge | **clipboard history**, newest first: text (up to three lines, ending in “…” when there is more) and pictures. Something copied since you last opened it pops in at the top while the others slide down. Click one to copy it again (it moves to the top), middle-click to delete it, scroll for older ones (`clipboardMaxItems`, 50). Click the round **magnifier** button next to the title: it widens into a search field — type, and only the text entries with it in them stay (any case). The panel stays open while you search; `Esc` clears the search and turns the field back into the button |
| hover the top-right corner of the frame | a small block with the **colour picker** pops out; click it, then click anywhere on the screen (right-click / `Esc` cancels): the hex code (`#1A2B3C`) is copied and shown in a notification with a swatch (kept in `~/.cache/frameshell/colors`, so the notification history shows it later too). It does not come out while a notification is on screen (`colorPicker: false` turns it off) |
| a notification arrives (bell on) | card at the top-right with app icon, name and text. | `SUPER+Space` | app switcher; hold SUPER, tap Space, let go of SUPER to switch (most recently used first; minimized windows are in the list too). The window you switch to gets the keyboard right away. Any other shortcut closes it without switching and then does what it does (`SUPER+arrows`, `SUPER+Q`, `SUPER+R` …), and so does a click anywhere outside it (also with SUPER held: SUPER + drag doesn't move windows while it is open) |
| middle-click an app in the bottom bar | close that window |

**Panels fit their content.** The app switcher and the launcher show only as many rows as there are apps/results, and scroll (Space, arrow keys or the mouse wheel) beyond `switcherMaxRows` / `launcherMaxRows`. The power menu, notification card, calendar (4–6 weeks), quick note and the Wi-Fi / Bluetooth list resize the same way, each with a maximum (`netMaxRows`, 6, for the list: longer lists scroll, with a thin bar on the right). The clipboard panel keeps the size of its concept and scrolls.

**Panels are part of the frame, not stuck onto it.** The frame, the notch and every panel are drawn as one silhouette: the border only follows the outside of that silhouette, so there is never a line between a panel and the frame (the separator lines in the concept art were an Inkscape leftover). Every corner and every curved joint uses the same radius as the concept (`cornerRadius` + border = 32px at 4K). Panels grow out of the frame as a small soft bump and open to full size, and fold back the same way; the edges move with sub-pixel precision, so there is no stepping. `animationSpeed` in `Config.qml` makes it faster or slower.

**Polish.** All motion is short and ends softly — nothing snaps into place (panels open in 0.4 s, most of the way in the first 0.2 s, and close in 0.25 s; hover, press and fade effects take 0.1–0.16 s). Buttons and app icons dip when pressed (nothing grows under the pointer; a round button is a little bigger while its panel is open); the calendar's today-circle pops in and the days slide in when you change month; the slider knob grows while you drag it; the wallpaper and the frame fade in at start. A soft shadow sits under the frame, the island, the panels, the app switcher, the launcher and every window (`shadows` / `shadowStrength` in `Config.qml`, for the windows too; switch `shadows` off on a very weak GPU or if your Qt is older than 6.9 — CachyOS ships a newer one). Windows themselves have no shadow, to keep the flat tiles of the concept: set `shadow = { enabled = true }` in `hyprland.lua` if you want one.

**Windows float inside the frame.** Every window has 15px of wallpaper around it (the **Window gap** slider in the Settings app's **Appearance** page, 5–20 px) — to the frame, the notch and the bottom bar, and between two windows — plus rounded corners, a 2px `#313131` border like the frame's (the focused window's border is light grey, `#c4c4c4`; in Noir and Mocha the borders have their own colours — each theme's `activeHint` and `inactiveHint` in `Config.qml`) and a soft shadow around it (size and darkness: `SHADOW_RANGE`, `SHADOW_OFFSET`, `SHADOW_ACTIVE` / `SHADOW_INACTIVE` in `hyprland.lua`; keep the range close to the 15px gap). Change the gap with that slider; `WINDOW_GAP` at the top of `hyprland.lua` is the gap until you move it (there also 0: windows touch the frame). A window gets the focus when you click it, not when the pointer passes over it (you can still scroll a window under the pointer); for focus-follows-mouse turn on **Focus on cursor** in the Settings app (Devices → Mouse).

**Maximize keeps the frame, fullscreen covers the screen.** `SUPER+F` maximizes a window: it fills the window area and keeps the 15px gap, the border and the rounded corners, with the notch, frame and bottom bar staying where they are. A window that opens into the tiles while one is maximized ends that maximize and opens beside it, on the right — where it would without the maximize. `F11` (and the fullscreen button of a video player, games) is real fullscreen: the window covers the whole screen — no frame, notch or bottom bar, square corners — and `F11` again (or `Esc` in a video) brings it back the way it was, maximized or in its tile. The app switcher (`SUPER+Space`) and the launcher (`SUPER+R`) still open on top; the rest of the shell, notifications included, is hidden until you leave fullscreen. Your other tiled windows stay drawn under a maximized or fullscreen window, so a see-through one (a terminal with `background_opacity`) shows them instead of only the wallpaper, blurred if it has blur (Hyprland blurs only the wallpaper behind tiled windows; such a window gets the real blur — and so do tiled windows while you move them over each other with `SUPER+Shift+arrows` or `SUPER+Z`, and while a new window opens between them, or a minimized one comes back, and they make room); clicks and keys still go to the maximized / fullscreen window, and floating windows are hidden as usual (Hyprland on its own stops drawing them all; `hyprland.lua` keeps them). On a workspace with tiling off, where every window floats, `SUPER+F` maximizes the window as a floating window instead (Hyprland can draw floating windows only over a maximized one, never under it): it gets the same size and place — the gap, the border and the rounded corners — and comes to the front, and the other windows stay where they are, under it, so a see-through one shows them (blurred, if it has blur). `SUPER+F` again puts it back where it was; dragged or resized with the mouse it is a normal window again (`SUPER+F` then maximizes it again). Hyprland and the app don't count it as maximized: a window that opens there opens over it, and one you go to with the keys, the app switcher, the dock or the island comes to the front. Turning tiling off keeps a maximized window maximized this way, and turning it on again gives it the normal maximize. `F11` there works the same way: the window covers the whole screen as a floating window (no border, square corners, in front), the app is told it is fullscreen (a browser or video player hides its own controls), and the other windows stay drawn under it. Hyprland hides the shell only for its own fullscreen, so `hyprland.lua` tells the shell to hide its frame, notch, bottom bar and notifications on that screen meanwhile — they fade out in the same moment and the same way as on a tiled workspace (the same 0.2 s fade, and back in when it ends; an event on Hyprland's event socket, `custom>>frameshell-cover`; `qs -c frame ipc call ui cover` does the same by hand; the app switcher and the launcher still open). `F11` again — or the app leaving fullscreen by itself (`Esc` in a video) — puts it back, maximized if it was maximized; `SUPER+F` makes it maximized. Apps that go fullscreen by themselves (a game, a video's fullscreen button) still get Hyprland's real fullscreen there (smoother for games: nothing else is drawn), with the other windows hidden. Minimized, moved to a tiled workspace or with tiling turned on, it stops covering the screen this way (with tiling on it gets the real fullscreen). The screen does not lock or switch off while something is fullscreen (a maximized window does not count). To keep fullscreen inside the frame like a maximized window instead, set `FULLSCREEN_LIKE_TILE = true` at the top of `hyprland.lua`.

Windows stay inside the frame: the shell reserves the frame, its border, the bottom bar **and the notch height** (so the notch never covers a title bar), and the window gap comes on top of that. Set `reserveNotch: false` in `Config.qml` if you'd rather let windows slide under it. With **Auto hide** on (the Settings app) the island and the dock are not reserved at all: windows go up to the thin frame, and the island and dock come out over them. **Notch mode** (the Settings app's Dock page) turns the bottom bar into a notch like the island, at the bottom: as tall as the bar, with the border, as wide as your apps need (at least as wide as one app, with the same margin), and the rest of the frame's bottom edge as thin as its sides; its height stays reserved like the bar's. With **Auto hide** too, the notch comes out — growing out of the middle of the edge, like the quick note and the clipboard — when the pointer touches the bottom edge anywhere in the middle 1500px (wider when the notch is), and stays while the pointer is in that strip as high as the dock (it takes the clicks there while the dock is out). The power button and the date then live in the bottom corners, like the colour picker top right: touch the corner and they come out, click to open the power menu or the calendar (`modules/PowerCorner.qml`, `modules/DateCorner.qml`).

## 5 · Make it yours

Every config file starts with a short comment that says what it is, and is split into labelled sections.

* **Shell options** — `~/.config/quickshell/frame/Config.qml` (saves reload the shell live): scale, `animationSpeed` (1 = normal, 0 = off), `clock24h`, `cornerRadius`, the maximum rows of the switcher / launcher / Wi-Fi + Bluetooth list (`netMaxRows`), `workspaceCount` / `workspaceMax` (workspace pills), `reserveNotch`, `dockIconSize` (app icons in the bottom bar, default 30), `popupScale` (size of the app switcher and the launcher, default 1; 0.8 = 20 % smaller), `plainSquares` (white placeholder squares like the concept art instead of app icons), notification timeout, wallpaper path, note height, `scrollStep` (how far one mouse-wheel notch scrolls the note and the clipboard, default 100 px; Qt's normal is 72), `lockPowerButtons` / `lockTheme` (lock screen, section 7), `clipboardMaxItems`, `colorPicker`, the colour themes (`themes`).
* **Wallpapers** — `SUPER+Ctrl+←` / `SUPER+Ctrl+→` switches between the pictures in `~/.local/share/frameshell/wallpapers` (PNG, JPG or WebP; 16:9 looks best, 3840×2160 on 4K), in the order of their file names, in a loop. Seven come with it: `arch-blue.png`, `blue-waves.png`, `chrome-hud.png`, `dark-bloom.png`, `meadow.png` (the default), `power-lines.png` and `sky-town.png`. **Add your own** with **+ Add** on the Settings app's Wallpaper page (it copies them in; a picture already there is skipped, another one with the same name gets a number) or by copying them into that folder — they show up in the switcher right away; the Wallpaper page also picks the wallpaper with a click; delete one and it is gone (if it was on screen, the default takes its place). The installer adds its pictures without touching yours. Your pick is kept in `~/.local/state/frameshell/wallpaper`. The **login screen** gets a copy of it (SDDM can't read your home folder): the installer makes `/usr/share/sddm/themes/pixie/assets/wallpaper.png` yours, so the shell replaces it whenever you switch (`scripts/wallpaper.sh`); the **lock screen** shows the picture itself. The default and the folder: `wallpaper` / `wallpaperDir` in `Config.qml`. A wallpaper from an earlier version (`~/.local/share/frameshell/wallpaper.png`, if it was your own) becomes `my-wallpaper.png` in the folder and stays on screen.
* **Border and corners** — the two border widths are sliders in the Settings app's **Appearance** page (0–4 px, 2 by default): **Window border** is the ring round every window (light on the focused one, dark on the others), **Frame border** the outline of the frame, the island, the panels and the pop-ups. They apply at once and are kept in `~/.local/state/frameshell/appearance.json` (`hyprland.lua` reads the window border from there when Hyprland starts). **Corner rounding** on the same page (20–30 px, 30 by default; kept in `appearance.json` too, `cornerRounding`) rounds the frame's four corners round the windows **and the windows' corners**; the island, the dock and the panels keep theirs. `cornerRadius` (default 30, made for 4K; use about 13 on a 1080p screen) in `Config.qml` is the radius of every other corner of the shell (and of those two until you move the slider). Save the file and everything updates right away (the shell restarts and hands it to Hyprland; `hyprland.lua` also reads it when Hyprland starts). They are in screen pixels, the unit Hyprland uses too. The space around windows is the **Window gap** slider on the same page (5–20 px, 15 by default; kept in `appearance.json` too, `windowGap`) — until you move it, `WINDOW_GAP` at the top of `hyprland.lua` (15). Only the fallback lock screen (`hyprlock.conf`) keeps its own copy of the border width (2px); change it there too if you want it to match.
* **Colours** — `Config.qml` (shell: the colour themes of the theme switcher, `SUPER+Ctrl+↑` / `SUPER+Ctrl+↓`), `kitty/frame.conf` (and `frame-noir.conf` / `frame-mocha.conf` for Noir and Mocha), `hyprlock.conf`, and for GTK apps `~/.local/share/themes/Frame/gtk-3.0/colors.css` + `gtk-4.0/colors.css` (keep the two alike; restart an app to see a change; Noir's and Mocha's GTK themes and Qt palettes are made from these by `themes/make-themes.py` — change their palettes there and run it). **Selected text** is `#3e3e3e` in Default, `#222222` in Noir and `#474859` in Mocha — in the shell (`textSelection` in `Config.qml`), kitty (`selection_background`), GTK apps (the Frame themes' `colors.css`; Firefox takes it from there too) and Qt apps (the qt5ct / qt6ct palettes' and the Kvantum themes' highlight). The thin lines between the power menu's rows and under the calendar's weekdays have their own colour, `divider` (the same `#313131` as the border, `outline`, to begin with). The screenshot screen has two of its own: `shotOutline`, the line round the picked area (the text colour to begin with), and `shotDim`, the darkening around it — black at 74 % (`#bd000000`, written `#AARRGGBB`) in every theme. The palette is `#1a1a1a` panel · `#313131` border · `#2a2a2a` selection · `#494949` the grey part of icons · `#ffb454` accent (battery while charging).
* **GTK theme** — the Frame themes (`themes/Frame`, `Frame-Noir`, `Frame-Mocha` in this folder; the theme switcher picks the one of the shell's theme) only change colours; the shapes come from adw-gtk3-dark. libadwaita apps ignore GTK themes, so `~/.config/gtk-4.0/gtk.css` loads the colours for them. Back to plain adw-gtk3: `gsettings set org.gnome.desktop.interface gtk-theme adw-gtk3-dark`, `gtk-theme-name=adw-gtk3-dark` in `~/.config/gtk-3.0/settings.ini` and `gtk-4.0/settings.ini`, and delete the `@import` line at the top of `~/.config/gtk-4.0/gtk.css`.
* **Qt theme** — Qt 5 and Qt 6 apps are drawn by **Kvantum** with its **Frame** theme (`~/.config/Kvantum/Frame`, from `themes/Kvantum/Frame` in this folder: KvLibadwaita's shapes in the Frame colours; `FrameNoir` and `FrameMocha` for the Noir and Mocha themes — the theme switcher switches them, and the palettes `colors/frame-noir.conf`, `frame-mocha.conf`). `hyprland.lua` sets `QT_QPA_PLATFORMTHEME=qt5ct`: Qt 5 apps then read `~/.config/qt5ct/qt5ct.conf`, Qt 6 apps `~/.config/qt6ct/qt6ct.conf` (qt6ct answers to that name too) — the same settings in both: Kvantum, the Frame palette (`colors/frame.conf`), YAMIS, Clarity City. Change them in the **qt5ct** / **qt6ct** apps, the Kvantum theme in **Kvantum Manager**; restart an app to see a change. New colours for a Kvantum theme: `themes/Kvantum/make-frame.py` rebuilds them (instructions at its top). Qt's plain look instead: `style=Fusion` in both files.
* **Title-bar buttons** — GTK apps show no minimise / maximise / close buttons (Hyprland handles the windows): `hyprland.lua` sets the button layout to none on every login (`gsettings set org.gnome.desktop.wm.preferences button-layout 'appmenu:'`), and `~/.config/gtk-3.0/gtk.css` + `~/.config/gtk-4.0/gtk.css` hide the buttons an app makes anyway (the `windowcontrols > button, headerbar .titlebutton` rule). Want them back: delete that line in `hyprland.lua` and that rule in both files, then run `gsettings reset org.gnome.desktop.wm.preferences button-layout`.
* **Animations** — the Caelestia-style curves are in the “ANIMATIONS” section of `hyprland.lua` (windows, and workspaces, which slide without fading) and in `Theme.qml` (the shell's own panels: the four durations at the top of the motion section).
* **App names** — the installer copies the menu entry (`.desktop` file) of kitty, Nautilus, GNOME Text Editor and Mission Center to `~/.local/share/applications` with only the name changed (that copy wins over the app's own): Terminal, Files, Text Editor, System Monitor. An app whose entry already has the name (Nautilus and GNOME Text Editor today) keeps its own entry. The copies are made again on every install, from the apps' current entries; each one starts with a `# frameshell` line. Other names: the `APP_NAMES` list in `install.sh` (`desktop file name:name`), then run the installer again. To get an app's own name back, delete its copy, e.g. `rm ~/.local/share/applications/kitty.desktop`.
* **Settings app** — the island's and the dock's **Auto hide**, and the dock's **Notch mode** and **Pinned apps** (by the ids of their `.desktop` files, `dockPinned`), are set in the Settings app (section 3), not in `Config.qml`; they are kept in `~/.local/state/quickshell/by-shell/…/state.json` with the notifications switch, the notification history next to it in `notifications.json` (delete it to empty the history). Its window is `modules/Settings.qml` (the pages and their switches are listed at its top; the Wallpaper page's **+ Add** runs `scripts/wallpaper-add.sh`, which uses zenity's file dialog) and tiles like any other app; its launcher entry is `~/.local/share/applications/frame-settings.desktop` (installed from `config/applications`), its icon `~/.local/share/icons/hicolor/scalable/apps/frame-settings.svg` (from `assets/icons` in the shell).
* **Apps behind the keys** — the “PROGRAMS” block at the top of `hyprland.lua`.
* **Mouse and cursor** — mouse speed and acceleration, scrolling and key repeat: the Settings app's **Devices** page. Until you change one there, Hyprland uses the last value of its line in the “INPUT” section of `hyprland.lua` (e.g. `shell_state("input.json", "mouseSpeed", -0.75)`: -1 … 1, 0 = unchanged; `"mouseAcceleration", true`: Hyprland's `accel_profile` `"adaptive"`, `false` = `"flat"`) — and the Settings app shows that value too. Cursor: `CURSOR_THEME` / `CURSOR_SIZE` in its “SETTINGS” section (the theme's folder name in `/usr/share/icons`). For the login screen and the computer's default cursor too, put the same name in `CURSOR_THEME` in `install.sh` (section 5 of it) and run it again. **Middle-click paste is off** (clicking the scroll wheel pastes nothing): `middle_click_paste = false` in the “misc” part of `hyprland.lua`, `gtk-enable-primary-paste=false` for GTK apps (both `settings.ini` files, and gsettings at login) and two `mouse_map … no_op` lines in the kitty configs (`~/.config/kitty/frame*.conf`); delete those to get it back. Firefox and VS Code handle it themselves: `middlemouse.paste` → `false` in Firefox's `about:config`, `"editor.selectionClipboard": false` in VS Code's settings.
* **Another monitor mode / scale** — the `hl.monitor` block, e.g. `mode = "3840x2160@144", scale = 1.5`.
* **Screenshots** — what happens after a capture (folder, file name `Screenshot_2026-10-15_10-24-07.png`, clipboard, the notification, which file manager opens) is in `~/.config/quickshell/frame/scripts/screenshot.sh`; the screenshot screen itself (its dimming, the colours of the tools, the line width) in `modules/Screenshot.qml`. The keys are `screenshot` / `screenshot_full` in the “PROGRAMS” block of `hyprland.lua`; `qs -c frame ipc call screenshot area` (or `screen`) starts one from a script.
* **Emoji picker and on-screen keyboard** — `modules/EmojiPicker.qml` (what happens with the emoji you pick: `scripts/emoji.sh`; the emoji themselves: `components/emoji.js`; to update them, download the `emojibase-data` package from npm and run `python3 tools/make-emoji.py <its folder> [newest Unicode version, 15.1]`) and `modules/OnScreenKeyboard.qml` (its keys, rows of 15 units, are at its top). The keys are `emoji_toggle` / `keyboard_toggle` in the “PROGRAMS” block of `hyprland.lua`; `qs -c frame ipc call emoji toggle` / `qs -c frame ipc call keyboard toggle` from a script. The keyboard sends its keys through Hyprland (`hl.dsp.send_shortcut`), so it types with your keyboard layout's key names (English (US) labels).
* **Automatic lock / screen off / suspend** — all off. Remove the `#` in front of a listener in `hypridle.conf` (lock after 5 min, screen off after 6, suspend after 30) and log out and back in; suspend needs the NVIDIA suspend services the installer enables.

## 6 · The icon pack (YAMIS)

The app icons come from **Yet Another Monochrome Icon Set** by DIRN (GPL-3). It is not included in this folder; `install.sh` asks, then downloads it from a GitHub mirror (`googIyEYES/YAMIS`, about 2.4 MB) into `~/.local/share/icons/YAMIS`, after checking that the archive only writes inside that folder. Already have it, or prefer the original from the KDE Store? Put the `YAMIS` folder in `~/.local/share/icons/` and the installer leaves it alone.
Four icons are set to other YAMIS icons on every install: **kitty** shows `utilities-terminal.svg` (the plain `>_` terminal), **Firefox** shows `firefox.alt.svg`, **GNOME Text Editor** shows `accessories-text-editor.svg` and **Nautilus** shows `system-file-manager.svg` (the folder icon it has today - kept even if a later YAMIS gives Nautilus its own icon), all in `apps/scalable` (the originals go to the backup folder). Change or remove the pairs in `YAMIS_SWAPS` in `install.sh`; to undo one, copy the original back from the backup folder.
GTK 3/4, Qt 5/6 (qt5ct / qt6ct) and the shell are all pointed at it. YAMIS inherits from Papirus-Dark, so apps it doesn't cover still get an icon. The shell's app icons can be switched to **Adwaita** or **Papirus** in the Settings app (Appearance → **App icons**): Qt takes the shell's icon theme once, when it starts (`//@ pragma IconTheme YAMIS` at the top of `shell.qml`), so for another pack `scripts/icon-index.py` lists the files of its icons (with hicolor — where apps put their own — and `/usr/share/pixmaps`) and the shell shows those (`services/IconPacks.qml`: add a theme to its `packs` to offer it too). The shell's own icons (battery, volume, bell, power …) are your 15 vector files, drawn in the shell itself.

## 7 · Login, lock and boot screen

**Login screen — Pixie.** The installer installs **SDDM** with the **Pixie** theme ([xCaptaiN09/pixie-sddm](https://github.com/xCaptaiN09/pixie-sddm), bundled in `extras/pixie-sddm`) to `/usr/share/sddm/themes/pixie`, and makes SDDM your login manager **from the next boot** (the running one is not touched). It writes `/etc/sddm.conf.d/zz-frameshell.conf`: Pixie is drawn for 1080p, so it is scaled to your screen (`QT_SCALE_FACTOR=2` on 4K), with your cursor and Num Lock on. It also writes `/etc/X11/xorg.conf.d/40-libinput.conf` (SDDM draws the login screen with X11): the mouse there moves at the desktop's default speed (`AccelSpeed` `-0.75`, `adaptive`) instead of X11's much faster one — change `AccelSpeed` there (with `sudo`, -1 … 1) for another; one of yours that said something else is kept as `40-libinput.conf.frameshell-backup`. The installer prints the command to go back to your old login manager, e.g. `sudo systemctl disable sddm && sudo systemctl enable cosmic-greeter`.

**The mouse cursor — Simp1e Adw Dark everywhere**, from the login screen on:
* **Login screen:** SDDM gets it from `CursorTheme=` in `zz-frameshell.conf` (and sets it with `xsetroot` / `xrdb`, which the installer installs). An `/etc/sddm.conf` with its own `CursorTheme=` line wins over that file; the installer warns about it.
* **The computer's default cursor:** `/usr/share/icons/default/index.theme` (from the package `default-cursors`) says `Inherits=Adwaita` out of the box — the black arrow you see wherever nothing else picks a cursor. The installer changes it to `Inherits=Simp1e-Adw-Dark` and `Size=24` (the original stays next to it as `index.theme.frameshell-backup`). A pacman hook, `/etc/pacman.d/hooks/zz-frameshell-cursor.hook`, sets it again after every update of `default-cursors`, and puts the original back if you uninstall Simp1e, so the default never points at a missing theme. Only that file is changed, nothing is added to the `default` folder. **Undo:** `sudo rm /etc/pacman.d/hooks/zz-frameshell-cursor.hook /usr/local/lib/frameshell/default-cursor.sh` and `sudo mv /usr/share/icons/default/index.theme.frameshell-backup /usr/share/icons/default/index.theme`.
* **After logging in:** Hyprland's own cursor is Simp1e from its first frame. `hyprland.lua` turns *hyprcursor* off (`cursor:enable_hyprcursor = false`): Simp1e is an XCursor theme, and with hyprcursor on Hyprland started with some other installed hyprcursor theme (a white arrow for about a second) until `hyprctl setcursor` switched to Simp1e.

**Lock screen — the same screen.** `SUPER+Escape`, *Lock* in the power menu and hypridle (before a suspend) all show Pixie's stacked clock, date and power buttons; any key or a click brings up the card with your picture, name and password field — that key only wakes it and is not typed into the password, like on the login screen (`Enter` unlocks, `Esc` goes back, a wrong password shakes the card). SDDM itself can't lock a running session, so the shell draws it (`lock.qml` + `modules/Lock.qml` / `LockView.qml`) from Pixie's own files: the same wallpaper, colours, fonts and layout as the login screen (checked side by side with the real SDDM greeter). It runs as its own small process, so restarting or editing the shell never touches a locked screen, and if it ever fails or crashes, **hyprlock** takes over automatically. `scripts/lock.sh` starts it at login and it waits in the background, unlocked, with everything loaded and the wallpaper already decoded, so locking only has to show it: it comes up at once (it takes about 100–150 MB of memory while it waits). After editing `lock.qml`, `modules/Lock.qml` or `LockView.qml`, run `pkill -f lock.qml` while unlocked (the next lock starts it again) or log out and back in. The password is checked by PAM like hyprlock does (`/etc/pam.d/hyprlock`). It fades in over your desktop and, once you are back in, fades out to it (Hyprland draws the desktop under the lock screen only during those fades — `misc:session_lock_xray`, switched by `lock.sh` and the lock screen — so nothing of it is drawn while you are away). Right before a suspend hypridle runs `lock.sh --instant`: the lock screen appears at once, never half see-through. `lockPowerButtons: false` in `Config.qml` hides suspend / restart / shut down on the lock screen (on the login screen they always show, like Pixie).

**The look matches the shell:** your desktop wallpaper (the installer copies it to the theme's `assets/wallpaper.png`, and the shell replaces that copy when you switch wallpapers) and the shell's greys instead of Pixie's green — white hours exactly above white minutes (the font's tabular clock digits), “Caps Lock is on” on the card when it is (Pixie says when Num Lock is on), the date and the power icons on one line, each as far from the top as from its side of the screen, and **the colours of the shell's colour theme**: each theme in `Config.qml` has `loginBackground` (the card), `loginText`, `loginAccent` (the avatar letter, the session icon), `loginHours` and `loginMinutes` (the clock), `loginCorners` (the date and the power icons and labels in the top corners), `loginField` (the password field's border and the round button), `loginAccentText` (the arrow) and `loginError` (the card after a wrong password) — Default's are light grey `#c4c4c4` on a `#1a1a1a` card. When you switch themes the shell writes them into `/usr/share/sddm/themes/pixie/theme.conf.user` (the installer makes that file yours, so no password is needed; SDDM reads it over `theme.conf`), and the lock screen reads the same two files, so both change at once — the login screen the next time it shows. **Change the rest for both** in `/usr/share/sddm/themes/pixie/theme.conf` (with `sudo`): `background=` (a file SDDM can read, e.g. in the theme's `assets/`; Pixie's forest is `assets/background.jpg`), `autoColor=true` (the accent picked from the wallpaper, Pixie's default), `use24HourClock=true`, `fontFamily=` (its colours are only used without `theme.conf.user`). The installer keeps an edited `theme.conf` when you run it again (the new one lands next to it as `theme.conf.new`). **Your picture** is `~/.face` (copied to the theme's `assets/avatar.jpg` by the installer; without one you get the first letter of your name).

**Boot screen — arch-darwin.** The Plymouth theme [armoredvortex/plymouth-theme-arch-darwin](https://github.com/armoredvortex/plymouth-theme-arch-darwin) (bundled in `extras/plymouth-arch-darwin`) goes to `/usr/share/plymouth/themes/arch-darwin`; the installer selects it and rebuilds the initramfs (`limine-mkinitcpio` or `mkinitcpio -P`). Back to the CachyOS one: `plymouth-set-default-theme -l` lists the themes, `sudo plymouth-set-default-theme <name>`, then rebuild the initramfs the same way. With an encrypted disk the installer asks first (default no): arch-darwin has no password box, you'd type the disk password without seeing dots.

**Boot loader — GRUB (only with `--grub`).** If your computer boots with GRUB, `./install.sh --grub` asks, then changes three settings in `/etc/default/grub` and nothing else: `GRUB_TIMEOUT_STYLE=hidden`, `GRUB_TIMEOUT=1` (press `Esc` while the computer starts to see the menu anyway; `GRUB_HIDDEN_WAIT` in `install.sh`) and `quiet splash` added to `GRUB_CMDLINE_LINUX_DEFAULT` when they are missing. Then it runs `sudo grub-mkconfig -o /boot/grub/grub.cfg`. Your kernel options, encryption settings and theme stay as they are. The file before the first change stays next to it as `/etc/default/grub.frameshell-backup`; to undo: `sudo cp /etc/default/grub.frameshell-backup /etc/default/grub && sudo grub-mkconfig -o /boot/grub/grub.cfg`. With other systems in the menu (dual boot) it warns you.

## 8 · NVIDIA notes

* `hyprland.lua` sets `LIBVA_DRIVER_NAME`, `__GLX_VENDOR_LIBRARY_NAME`, `NVD_BACKEND` and the toolkit variables. `GBM_BACKEND` is **not** set on purpose (it crashes Firefox on several driver versions).
* The installer enables DRM modesetting (`/etc/modprobe.d/frame-nvidia.conf`) and the `nvidia-suspend/-resume/-hibernate` services if they exist. No driver yet? On CachyOS `sudo chwd -a` installs the right one.
* The mouse cursor: on an NVIDIA card `hyprland.lua` lets Hyprland draw the cursor itself (`no_hardware_cursors = 1`), because NVIDIA's hardware cursor often keeps the default arrow or flickers. Other cards keep the hardware cursor.
* Hybrid laptop with an iGPU: set `AQ_DRM_DEVICES` (see the comment in `hyprland.lua`).

## 9 · If something is off

| Symptom | Fix |
| --- | --- |
| Black screen with only a wallpaper colour / no frame | `qs -c frame` in a terminal shows the error; `hyprctl layers` should list `frame-overlay` |
| No notifications | the bell is off by default (hover the notch → bell). Also make sure `mako`/`dunst`/`swaync` are not installed: `sudo pacman -Rns mako dunst swaync` |
| Brightness slider missing | your monitor needs DDC/CI enabled in its on-screen menu, and you must be in the `i2c` group (the installer does this — reboot once). Test: `ddcutil detect` |
| Bar shows letters instead of icons | the app has no icon in YAMIS / Papirus. Check that YAMIS is installed (`ls ~/.local/share/icons/YAMIS`) and `qt6-svg` is present. `Config.plainSquares` forces squares everywhere |
| `F11` keeps the window inside the frame | check that `FULLSCREEN_LIKE_TILE` is `false` in `hyprland.lua` and `hyprctl version` (needs ≥ 0.55) |
| `SUPER+Space` opens the switcher but letting go doesn't switch | check that `hyprland.lua` still has the two `SUPER_L`/`SUPER_R` release binds; pressing `Enter` in the switcher also confirms |
| `SUPER+R` does nothing | the shell isn't running (`qs -c frame` shows why) |
| Hyprland says the config is invalid | check the version: `hyprctl version` (needs ≥ 0.55, Lua config). Older versions use `hyprland.conf` and cannot read this file |
| Old login screen still there after a reboot | `systemctl status display-manager` shows which one runs; `/etc/sddm.conf` with its own `Current=` line wins over `zz-frameshell.conf` — remove that line |
| Login screen black / SDDM doesn't start | `Ctrl+Alt+F3`, log in, then go back to your old one: `sudo systemctl disable sddm && sudo systemctl enable <old one, e.g. cosmic-greeter>` and reboot. `journalctl -b -u sddm` shows why |
| Lock screen shows an error text instead of the clock | the lock screen died and nothing took over. `Ctrl+Alt+F3`, log in, run `hyprctl --instance 0 dispatch 'hl.dsp.exec_cmd("hyprlock")'`, go back with `Ctrl+Alt+F1` (or `F2`) and unlock in hyprlock. To see why it failed: run `qs -p ~/.config/quickshell/frame/lock.qml` in a terminal — it locks the screen and prints its messages there (unlock to end it) |
| Log out ends on a black screen / an app was still open | `~/.local/state/frameshell/logout.log` shows each step: how many apps were open, how long they took to close (at most 3 s, then they close with the session) and when Hyprland was gone. Log out first asks every app to close, quits Hyprland, waits until it and `start-hyprland` are gone, then ends the session (`loginctl terminate-session`), so nothing keeps running. If SDDM still leaves a black screen, `Ctrl+Alt+F3`, log in and `sudo systemctl restart sddm`; `journalctl -b -u sddm` shows why |
| Boot screen unchanged | `plymouth` must be in `HOOKS=(…)` of `/etc/mkinitcpio.conf` and `splash` on the kernel command line (CachyOS has both); after changing either, rebuild the initramfs |
| `Print` does nothing / “Screenshot failed” | The shell takes the picture itself (Hyprland's screen capture, `wlr-screencopy`): the shell must be running (`qs -c frame ipc call screenshot area` in a terminal says if it isn't). “Screenshot failed” means the screen could not be captured within 3 seconds. Stuck without shortcuts after a crash: `SUPER+Ctrl+Alt+Esc`, or `hyprctl dispatch 'hl.dsp.submap("reset")'` |
| Another cursor on the login screen, or for a moment after logging in | `cat /usr/share/icons/default/index.theme` should show `Inherits=Simp1e-Adw-Dark` and `Size=24`, and `grep -i cursor /etc/sddm.conf` should print nothing (a `CursorTheme=` line there wins over `zz-frameshell.conf` — remove it). Then run `./install.sh` again (it checks both) and reboot — SDDM reads its settings when it starts |
| The mouse cursor is the default arrow | the cursor theme is missing: `ls /usr/share/icons | grep -i simp1e` should list `Simp1e-Adw-Dark`. If not, run `./install.sh` without `--no-packages` (it installs the AUR package, and an AUR helper first if needed) or `paru -S xcursor-simp1e-adw-dark`. Then log out and back in — Hyprland loads its cursor at login |
| Videos open in another app, not Celluloid | run `./install.sh --no-packages --no-login --no-boot` again (it sets every video type), or for one type: `xdg-mime default io.github.celluloid_player.Celluloid.desktop video/mp4`. `xdg-mime query default video/mp4` shows the current one |
| Folders open in another app, not Nautilus | run `xdg-mime default org.gnome.Nautilus.desktop inode/directory` (`xdg-mime query default inode/directory` should then print `org.gnome.Nautilus.desktop`). Some apps decide this themselves — check their settings. “Show in folder” still opening Thunar right after the update: log out and in once (a Thunar that was already running keeps answering until then) |
| A GTK app still has the old colours | restart it (GTK reads its theme at start). `gsettings get org.gnome.desktop.interface gtk-theme` should print `'Frame'`; if not, run `gsettings set org.gnome.desktop.interface gtk-theme Frame`. Flatpak apps keep their own look |
| Firefox's bars don't follow the GTK colours | in `about:config` set `widget.gtk.libadwaita-colors.enabled` to `false` and restart Firefox |
| Want the old setup back | everything replaced is in `~/.config/frame-backup-<date>/` |
